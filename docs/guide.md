# Руководство пользователя и разработчика

Личная Kanban-доска системного аналитика: бумажные стикеры, маркерные надписи, дневное отражение окна и вечерний свет лампы. Все задачи сохраняются в локальном файле SQLite.

## Быстрый запуск: macOS, Linux, Windows

Нужны **Node.js 24+** и npm. SQLite встроен в Node.js: устанавливать PostgreSQL, SQLite, Homebrew, Docker или компилятор для драйвера базы не нужно. Приложению достаточно права запускать Node.js и записывать файлы в папку проекта. Возможность запуска Node.js на рабочем ноутбуке зависит от правил вашей организации.

Откройте терминал в папке проекта и выполните:

```sh
npm start
```

Можно использовать готовый файл запуска из корня проекта:

| ОС | Файл | Как запустить |
| --- | --- | --- |
| macOS | `start.command` | Двойной щелчок в Finder; откроется Терминал |
| Linux | `start.sh` | `bash start.sh` в терминале или `./start.sh` |
| Windows | `start.bat` | Двойной щелчок в Проводнике или запуск из терминала |

Все три файла переходят в папку проекта, проверяют Node.js 24+ и npm, затем выполняют тот же `npm start`. Их можно запускать из другой рабочей папки; пути с пробелами поддерживаются. Перемещайте их вместе с проектом, а для рабочего стола создайте ярлык. Windows не требует Bash или изменения политики PowerShell.

Если после распаковки архива macOS/Linux потеряли право выполнения файлов, выполните в папке проекта `chmod +x start.command start.sh`. В Linux можно сразу использовать `bash start.sh` без изменения прав. При ошибке запуска файлы для двойного щелчка оставляют сообщение в окне до нажатия клавиши.

Сценарий сам установит npm-зависимости по `package-lock.json`, создаст отдельную базу, применит миграции, соберёт интерфейс и откроет **http://localhost:3000**. Терминал оставьте открытым. Для остановки нажмите **Ctrl+C**; данные сохранятся. После перезагрузки компьютера снова выполните `npm start`.

Первый запуск требует интернета для установки зависимостей. Дальнейшая работа автономна: шрифты, текстуры и графика поставляются с приложением. Повторная установка npm-пакетов выполняется только при изменении lock-файла или отсутствии зависимостей.

Приложение слушает только `127.0.0.1:3000`. SQLite работает внутри сервера и не занимает отдельный порт. На другой ОС устанавливайте зависимости заново: не переносите `node_modules` между компьютерами.

`BOARD_NO_OPEN=1 npm start` запускает приложение без автоматического открытия браузера. Если порт занят, запуск завершается с объяснением, а данные сохраняются. Одновременно работает один экземпляр стартового сценария.

В PowerShell: `$env:BOARD_NO_OPEN='1'; npm start`. Переменная `BOARD_DATA_DIR` позволяет задать другую папку данных; по умолчанию используется `.local` внутри проекта. Храните базу на локальном диске, вне сетевых папок и папок с активной облачной синхронизацией.

В некоторых версиях Node.js 24 встроенный SQLite выводит `ExperimentalWarning`; это предупреждение о статусе API Node.js, запуск продолжается. Запуск проверен на macOS. Код рассчитан также на Windows и Linux, но проверка на этих ОС ещё предстоит.

## Ежедневная работа

- Нажмите **+ Задача** или **+ Добавить** в колонке. Для создания достаточно названия.
- Нажмите стикер, чтобы открыть карточку. Изменения полей применяются кнопкой **Сохранить**. Закрытие изменённой карточки требует подтверждения.
- Перетаскивайте стикер за шесть тёмных маркерных штрихов внутри правого верхнего угла. Ручка видна постоянно, область захвата увеличена. С клавиатуры: сфокусируйте ручку, нажмите пробел, используйте стрелки, снова нажмите пробел. Escape отменяет перемещение.
- При переносе стикер приподнимается, в целевой колонке появляется место для него, а соседние карточки плавно освобождают пространство. После отпускания стикер остаётся на выбранном месте во время сохранения. Если сервер отклоняет изменение, доска возвращается к сохранённому состоянию и показывает ошибку. Системное уменьшение движения отключает анимации.
- Для перемещения без перетаскивания измените **Этап** в карточке; кнопки ↑ / ↓ на стикере меняют порядок внутри колонки.
- Цвет означает категорию: ваша задача, коллега или смежная команда. Ответственный, команда и проект выбираются независимо.
- Справочники сотрудников, команд и проектов находятся в **Настройках**. Нажмите карандаш у команды, отметьте её сотрудников и проекты и сохраните. Сотрудник может входить в несколько команд, а команда — участвовать в нескольких проектах. В карточке задачи связанные записи предлагаются первыми. Там же — лимит задач в работе и переключатель «Отключить отражение».
- **Сегодня** объединяет фокус дня, сроки, напоминания, блокировки и ожидания без даты. Даты рассчитываются в часовом поясе браузера, завершённые и архивные задачи исключаются.
- У ожидания своя дата напоминания. Напоминания отображаются, когда приложение открыто; отправки почты и фоновых уведомлений нет.
- Зависимости нельзя замкнуть в круг. Если завершить задачу до её зависимостей, приложение попросит подтверждение.
- В архив можно отправить завершённую задачу. Откройте её в архиве и нажмите **Вернуть из архива**, чтобы вернуть на доску.
- Название колонки меняется по нажатию на него; смысл этапа сохраняется.
- Солнце и луна переключают освещение. Галочка «Отключить отражение» полностью убирает окно и зелень за стеклом. Если отражение включено, системная настройка уменьшенного движения оставляет его неподвижным.

Первая доска пустая. Кнопка **Посмотреть на примерах** создаёт демонстрационные задачи только по вашему действию и только на пустой доске.

Доска автоматически занимает доступную высоту окна браузера. Рамка и лоток остаются видимыми; длинные списки задач прокручиваются внутри колонок, а «Сегодня» и архив — внутри рабочей области. На небольшом экране верхняя панель также прокручивается отдельно.

## Вид карточек и мобильный интерфейс

В панели доски есть переключатель **Подробно / Компактно** с пиктограммами. Подробный вид показывает прежний набор полей. Компактный оставляет полное название, ответственного, срок, категорию и сигналы фокуса, высокого приоритета и блокировки; подробности доступны по нажатию. На компьютере оба режима поддерживают перетаскивание и клавиатуру.

На экранах до 760 px доска превращается в один вертикальный список со сворачиваемыми этапами. Нижняя панель открывает доску, «Сегодня», создание задачи и меню «Ещё» (архив, настройки, освещение). Кнопка рядом с поиском открывает фильтры. Стикер можно перенести пальцем за ручку **Перенести** или удержать его текст около четверти секунды и потянуть. Обычный свайп по тексту прокручивает список. Линия показывает место вставки; свёрнутый этап можно использовать как цель (удержание над ним раскрывает список). Видимые стрелки **↑ / ↓** меняют порядок внутри этапа. Меню `…` позволяет выбрать этап без перетаскивания. Поиск раскрывает этапы с результатами; после создания новый стикер показывается автоматически.

Мобильная карточка открывается на весь экран: этап, следующий шаг и основные поля сверху; остальные разделы можно раскрывать. Кнопки сохранения находятся вне прокручиваемого листа. Ошибка в свёрнутом разделе раскрывает его и переводит фокус на поле.

Плотность карточек хранится в `localStorage` этого браузера, отдельно для узкого и широкого экрана; по умолчанию на телефоне включён компактный вид. Эта настройка не переносится с JSON-экспортом доски. Данные задач по-прежнему сохраняются в SQLite.

## Эскиз

Вкладка **«Эскиз»** — свободное пространство на той же эмалевой доске. На телефоне она доступна в нижней навигации.

- **Маркер**: выберите один из четырёх цветов и толщину, затем рисуйте мышью, пером или пальцем.
- **Масштаб**: при открытии приложения — 100%. Кнопки «−» и «+» меняют его вручную; нажатие на процент вписывает холст в окно.
- **Готовые блоки**: прямоугольник, овал, ромб «Решение», цилиндр «База», стрелка и отдельный текст. Выберите инструмент, нажмите на холст для стандартного размера или растяните фигуру.
- **Подписи**: после добавления фигуры рядом с ней откроется бумажное поле ввода, обычно справа; у правого края оно появится слева. Enter сохраняет текст; Shift+Enter добавляет строку. Для редактирования включите «Выбрать» и дважды нажмите на фигуру либо нажмите карандаш над правым верхним углом выделения.
- **Перемещение и размер**: инструмент «Выбрать», перетаскивание элемента или его нижнего правого уголка. Размер можно менять и у свободных штрихов маркера. Стрелки клавиатуры перемещают выбранный элемент; Shift ускоряет шаг. В режиме «Выбрать» серая корзинка над правым верхним углом удаляет элемент; при наведении краснеет и показывает «Удалить элемент». В режиме «Рука» корзинки нет. Delete/Backspace также удаляет, Ctrl/⌘ Z отменяет удаление. Tab позволяет последовательно выбрать элементы, Enter открывает подпись.
- **Магнитный стиратель слева**: нажать — очистить рисунок; удерживать и провести по доске — стереть участок. После отпускания стиратель возвращается на магнит. Эмаль и отражение остаются видны через стёртые участки. Под губкой постоянно видна бумажная подсказка. При переносе размер губки сохраняется; на широком экране она крупнее, но ограничена по размеру.
- **Отмена**: кнопки ↶/↷, Ctrl/⌘+Z, Ctrl/⌘+Shift+Z или Ctrl+Y. История последних 30 действий действует до перезагрузки страницы; очистка доски тоже отменяется.
- **Масштаб**: −/+, нажатие на процент вписывает схему целиком. «Рука» переносит элементы; если потянуть пустую область, она перемещает сам холст. На узком экране начальный масштаб увеличен для читаемости.
- **Быстрые инструменты** (латинская раскладка): B — маркер, V — выбор, H — рука, T — текст. Escape отменяет текущий жест.

Изменения сохраняются автоматически через полсекунды после завершения действия. Статус «Сохранено» появляется после ответа сервера. При ошибке показана причина и доступна повторная попытка. Несохранённый рисунок дополнительно хранится в черновике текущей вкладки браузера; закрывать её до успешного сохранения не следует. Набранную подпись подтвердите кнопкой «Готово»; при переходе в другой раздел она применяется автоматически.

Эскиз имеет отдельную ревизию: редактирование задач не мешает рисованию. При конфликте двух вкладок приложение сохраняет ваш черновик и предлагает явно выбрать, какую версию оставить. Совместное рисование не реализовано.

Экспорт JSON версии **2** включает эскиз. Импорт принимает версии 1 и 2; старые копии версии 1 без эскиза восстанавливаются с пустым полотном. Импорт заменяет всю доску, включая рисунок. Для открытия копии версии 2 нужна версия приложения с поддержкой «Эскиза».

## Где находятся данные

Всё локальное состояние лежит в `.local/`, исключённой из Git:

| Путь | Содержимое |
| --- | --- |
| `.local/board.sqlite` | Основная база SQLite; не удалять при обновлении проекта |
| `.local/board.sqlite-wal`, `.local/board.sqlite-shm` | Рабочие файлы SQLite; не удалять во время работы |
| `.local/backups/` | Полные копии базы перед миграциями и ручные копии |
| `.local/start.lock/` | Блокировка стартового сценария |

На macOS/Linux новая папка данных создаётся с правами `0700`, файл базы — `0600`. В Windows используются права доступа папки вашего пользователя. Пароля базы и отдельной службы нет.

Очистка данных браузера не удаляет задачи. Удаление папки проекта вместе с `.local` удалит локальную базу: храните резервные копии отдельно.

## Резервное копирование и восстановление

Основной способ: **Настройки → Скачать копию**. JSON содержит задачи, зависимости, чек-листы, ссылки, справочники, колонки и настройки.

Для восстановления выберите **Восстановить из файла**. Приложение проверит формат и связи, покажет количество задач и дату выгрузки, предложит скачать текущую доску. Только после подтверждения данные заменяются одной транзакцией. Повреждённый файл оставляет существующую доску без изменений.

Полная копия SQLite при работающем или остановленном приложении:

```sh
npm run backup
```

Файл `.sqlite` появится в `.local/backups/`. Копия создаётся штатным SQLite Backup API с учётом журнала WAL и проверяется через `quick_check`. Сохраните её отдельно от проекта. Не копируйте только основной файл открытой базы вручную: последние изменения могут находиться в WAL.

Для восстановления полной копии остановите приложение через Ctrl+C. Переместите текущий `board.sqlite` и его `-wal`/`-shm` (если они остались) вместе в отдельную папку. Скопируйте резервный `.sqlite` как `.local/board.sqlite`, затем выполните `npm start`. Используйте совместимую версию приложения. Файл `.sqlite` не загружается в JSON-импорт интерфейса. Для переноса задач между компьютерами удобнее JSON.

Перед новой SQL-миграцией уже существующей базы создаётся полная копия. Миграции применяются транзакционно; при ошибке изменения схемы откатываются, приложение не запускается. Применённые SQL-файлы нельзя редактировать: добавляйте новый файл миграции. При несовпадении контрольной суммы запуск прекращается.

## Переход с PostgreSQL

Формат JSON-копии остался прежним. Если вы использовали раннюю версию с PostgreSQL, сохраните JSON-экспорт перед переходом. Новый запуск использует только SQLite и не запускает PostgreSQL.

На другом компьютере экспортируйте доску через настройки прежней версии. В новой установке восстановите JSON через интерфейс. При обновлении существующей папки проекта сохраните экспорт как `.local/postgres-export.json` до первого запуска SQLite. Если новая база ещё не содержит доску, приложение проверит и перенесёт JSON одной транзакцией, сохранив ревизию, затем сверит результат. Повторные запуски не импортируют файл заново. Старый кластер без экспорта останавливает запуск с объяснением вместо создания пустой доски; повреждённый экспорт не импортируется.

Старые `.dump` восстанавливаются средствами PostgreSQL, а не SQLite. Сохраните их до проверки переноса. Последующие изменения SQLite не синхронизируются со старой базой.

## Разработка

### Учебные команды и проверка

`npm run seed:teams` добавляет примеры на **запущенную основную доску**: три команды («Платежи», «Личный кабинет», «Платформа»), девять сотрудников и 18 задач. Существующие задачи и настройки сохраняются; перед добавлением JSON-копия записывается в `.local/backups/`. Повторный запуск не дублирует существующие примеры. Даты новых примеров рассчитываются от дня запуска. Роли указаны в именах сотрудников, команда назначается на задаче; отдельного профиля сотрудника с членством в команде в текущей модели нет.

`npm run qa` собирает приложение и открывает для доступа тестовую доску по **http://localhost:3100**. Её SQLite-база находится в `.local/qa/`; основная доска на порту 3000 не затрагивается. При первом запуске автоматически добавляются учебные команды. Браузер откройте вручную, для остановки используйте Ctrl+C. Все изменения в QA-базе сохраняются между запусками.

Последний отчёт: [проверка функциональности и UX/UI от 31 октября 2026](qa-2026-10-31.md).

Стек: React, TypeScript, Vite, dnd-kit, Fastify, SQLite (`node:sqlite`), Drizzle ORM, Zod. Исходники разделены на `src/` (интерфейс), `shared/` (модель и правила), `server/` (API, схема и миграции), `scripts/` (жизненный цикл).

Для работы с быстрым обновлением интерфейса:

```sh
# Терминал 1: приложение и база, разрешённый dev-origin
NODE_ENV=development npm start

# Терминал 2: Vite с прокси API
npm run dev
```

Откройте `http://localhost:5173`. Обычный пользовательский запуск остаётся `npm start`.

Проверки:

```sh
npm test                 # Правила зависимостей, даты, проверки импорта
npm run build           # TypeScript и production-сборка
npm run test:integration # Временные SQLite-базы и API; запускать сервер не нужно
```

Интеграционные тесты используют временные папки ОС и не обращаются к пользовательской базе. Проверяют API, порядок карточек, зависимости, конкурентные ревизии, экспорт/импорт, откат ошибки записи и миграции, резервное копирование, повторный запуск и перенос JSON из прежней версии.

## Локальный API

- `GET /api/board` — полное состояние и номер ревизии.
- `GET /api/sketch` — рисунок и отдельная ревизия.
- `POST /api/sketch` — `{ revision, items }`; проверяет геометрию, ограничения объёма и конфликт изменений.
- `GET /api/health` — готовность приложения и базы.
- `GET /api/export` — версионная JSON-копия.
- `POST /api/actions` — `{ revision, action }`; действия `saveTask`, `moveTask`, `deleteTask`, `saveDirectory`, `deleteDirectory`, `renameColumn`, `settings`, `import`, `demo`.

Форматы типизированы и валидируются в `shared/model.ts`. Запрос изменения должен иметь допустимый локальный `Origin`, JSON Content-Type и заголовок `X-Board-Request: 1`. Сервер проверяет Host и не включает CORS. Браузер работает только через API; файл SQLite ему не отдаётся.

Две вкладки защищены номером ревизии: устаревшее изменение отклоняется с сообщением; пользователь может повторить его после обновления состояния. Операции одной базы последовательно выполняются в серверной очереди; запись использует `BEGIN IMMEDIATE`, внешние ключи и WAL с `synchronous=FULL`. Drizzle обращается к встроенному SQLite через адаптер `sqlite-proxy`; сетевого посредника нет. В текущей личной версии запись атомарно заменяет строки одной небольшой доски, сохраняя идентификаторы; при переходе к большой многопользовательской системе этот слой следует заменить точечными обновлениями.

## Границы первой версии

Это локальное приложение для одного владельца, проверенное на macOS. Сотрудники в справочнике — ответственные, а не аккаунты. Доступ из интернета, совместное редактирование, Docker, интеграции и фоновые уведомления пока не реализованы. Для будущего размещения на собственном сервере потребуются авторизация и отдельная настройка доступа; текущий сервер намеренно доступен только с этого компьютера.

Шрифты Caveat и Neucha распространяются по SIL Open Font License; копии лицензий находятся в `public/licenses/`. Фотореалистичные материалы в `public/materials/` созданы с помощью imagegen по дневному и вечернему рендерам. Исходные запросы сохранены в `docs/material-prompts.json`.

Эмаль и металлическая рамка используют отдельные дневной и вечерний материалы; бумага и маркеры — изображения с прозрачностью. Текст и все элементы управления остаются интерактивными. Отражение состоит из неподвижной фотографии окна с прозрачными стёклами и отдельных фотографий веточек за ней. Ближние и дальние веточки качаются вокруг основания с небольшими задержками, возвратом после порыва и спокойными интервалами. Форма листьев не деформируется. Анимация работает через CSS и приостанавливается в скрытой вкладке; WebGL не требуется. Материалы и запросы: `docs/foliage-layers.md`.

Галочка «Отключить отражение» полностью удаляет окно и зелень; при включённом отражении `prefers-reduced-motion` отключает только анимацию. Тени бумаги меняют направление в вечернем освещении. Все материалы доступны без интернета.

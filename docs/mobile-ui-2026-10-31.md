# Мобильная доска и плотность карточек

Реализован второй согласованный концепт: один вертикальный список этапов, бумажные карточки и полноэкранный редактор. Порог мобильного представления — 760 CSS px.

Переключатель «Подробно / Компактно» расположен в панели фильтров на компьютере и под поиском на телефоне. Подписи дополнены нарисованными пиктограммами; выбранная кнопка имеет aria-pressed. Полное название задачи остаётся доступным в обоих режимах. На десктопе длинный ответственный сокращается с подсказкой; на мобильном переносится.

Выбор хранится локально в браузере отдельно для двух размеров экрана. По умолчанию: подробный десктоп, компактный телефон. При недоступном localStorage переключатель работает в текущем сеансе. Схема SQLite и формат экспорта не менялись.

## Проверка

- `npm run build`: успешно; прежние предупреждения Rollup об аннотациях Zod.
- `npm test`: 11/11, включая порядок и зависимые задачи.
- `npm run test:integration`: 4/4, включая реальные SQLite/API, сохранность и откат.
- Проверки изменений данных выполнялись на отдельной доске localhost:3100, `.local/qa`, а не в пользовательской базе.
- Браузер: 390×844, 320×640, 740×390 и 1280×720. Горизонтального переполнения страницы не обнаружено. Нижняя навигация отделена от списка; редактор и действия укладываются в видимую область.
- Проверены сворачивание этапов, два вида карточек, сохранение выбора после reload, фильтр команды, раскрытие результатов, сброс фильтра, «Сегодня», дневное/вечернее оформление.
- Создание из нижней навигации раскрывает «Входящие» и фокусирует новый стикер. Меню меняет этап и порядок; изменения подтверждены UI.
- Сохранение следующего шага проверено повторным открытием. Пустой пункт чек-листа в свёрнутом разделе вызывает русскую ошибку, раскрытие раздела и фокус на поле. Исправление позволяет сохранить.
- На десктопе компактная карточка перенесена Space → ArrowRight → Space; после reload осталась в новом этапе.

## Ограничения проверки

Использован браузер с изменением размера viewport, не физический телефон. Для экранной клавиатуры предусмотрены VisualViewport и interactive-widget=resizes-content, для вырезов — safe-area-inset; фактическую клавиатуру iOS/Android и жесты на устройстве нужно дополнительно проверить. Приложение по-прежнему слушает только localhost; доступ с другого устройства по сети этим изменением не включается.

## Исправление мобильного переноса

Добавлены TouchSensor (удержание 220 мс на тексте, немедленный захват за ручку), отдельный MouseSensor для узкого окна и постоянно видимые кнопки порядка 44×44 px. Перенос показывает поднятый стикер и линию вставки; свёрнутые этапы принимают карточки и раскрываются при удержании. Финальное место определяется по native touchend/pointerup, включая быстрые жесты, для которых библиотека ещё не успела обновить delta. Предпросмотр сохраняется до ответа API, ошибка возвращает сохранённый порядок.

Проверено в Chrome DevTools Pixel 7 (412×915, сенсорная эмуляция) на отдельной QA-базе: перенос из «В работе» в свёрнутые «Входящие», перестановка внутри этапа, видимая стрелка вверх и обычный свайп прокрутки. Дополнительно проверен перенос мышью в узком IAB. Физический телефон в проверке не использовался. Код и стили десктопной доски не менялись.

Автоматические проверки после изменения: 14 unit-тестов (включая новые проверки мобильного порядка, границ, фильтров и свёрнутых этапов), 4 интеграционных теста SQLite/API и production-сборка.
